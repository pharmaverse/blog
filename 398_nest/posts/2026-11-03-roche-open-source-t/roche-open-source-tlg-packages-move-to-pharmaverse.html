Roche Open-Source TLG Packages Move to pharmaverse

Key clinical reporting and exploration packages, including {rtables}, {tern} and the {teal} framework, have moved from insightsengineering to the pharmaverse GitHub organization. Here is why, and what it means for you.

Written on behalf of the NEST team.

Over the past few months, we have reached an important milestone in our open-source journey: transitioning key clinical reporting and exploratory analysis R packages from the insightsengineering GitHub organization into the pharmaverse.

The recent migration of the {teal} framework marks another step in this transition, bringing these framework packages under pharmaverse governance.

Why the Move to pharmaverse?

When we initially incubated these packages under insightsengineering, our primary goal was to modernize clinical reporting workflows and pioneer reproducible, interactive data exploration. However, open source in the pharmaceutical industry is at its most powerful when built with the community, not just for it.

Moving these packages directly under the pharmaverse organization:

  1. Breaks Down Barriers to Collaboration: Moving beyond decision-making led by a single organization allows other companies and community contributors to help shape priorities, roadmaps, and development.
  2. Harmonizes the Ecosystem: Consolidating standard clinical data manipulation, table creation, and exploration tools into a unified organization makes it easier for teams across industry sponsors and CROs to adopt, contribute to, and integrate tools.
  3. Fosters Long-Term Sustainability: It paves the way for joint ownership, core co-maintainership, and broader industry governance across life-science data science stacks.

What Packages Have Migrated?

The transition has taken place gradually over the past several months and includes foundational packages spanning tabular reporting, clinical analysis modules, and interactive exploration:

  • Reporting & Tabulation Foundation:
    • formatters — Core rendering engine for ASCII and rich-text table layouts.
    • rtables — Tabular summaries and complex multi-level layout generation.
    • rlistings — Clinical listings supporting pagination and display formatting.
    • cards & cardx — Analysis results datasets (ARDs) creation and statistical helper utilities.
  • Analysis & Automation Modules:
    • tern — Standard clinical trial summary tables, figures, and listings (TLGs).
    • autoslider.core — Automated presentation/slide generation engines.
  • Interactive Exploration ({teal} ecosystem):
    • The entire suite of {teal} framework core packages (including teal, teal.code, teal.data, teal.widgets, teal.reporter, teal.slice, teal.logger, teal.picks).

What Changes for Users and Developers?

  • CRAN / Release Users: Zero breaking changes. The repository move does not change existing released package versions. If you install these versions via CRAN or an internal mirror, no changes to your R code are required as a result of the move.
  • GitHub Remotes & Dev Versions: GitHub automatically handles redirection for repository moves, but we recommend updating your development remotes and remotes::install_github() / pak::pkg_install() references from insightsengineering/<pkg> to pharmaverse/<pkg>:
pak::pkg_install("pharmaverse/teal")
pak::pkg_install("pharmaverse/rtables")
  • Contributing & Issue Tracking: For the migrated packages, all active issue trackers, feature requests, and discussions are now centralized under pharmaverse/<repo>. You are welcome to submit PRs, suggest features, or report bugs directly there.

Looking Ahead

As these packages become part of pharmaverse, we look forward to broader participation and shared stewardship across the community. We welcome contributions from companies and individuals to help shape their direction and support their continued development.
